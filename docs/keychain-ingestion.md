# Keychain-backed archive decryption

`research/keychain_decryption.py` supplies the archive verifier's caller-owned authenticated-decryption boundary on macOS. `scripts/macos_decrypt_record.swift` is its private subprocess protocol, not a display/inspection command. Never invoke the native helper in a terminal or chat tool that would expose its stdout: the Python callback must capture it privately in memory.

The operator supplies independently trusted fingerprints for the compiled helper and normalized public certificate. The callback checks the helper's ownership/private permissions/hash, recipient files, certificate pin and private scratch directory. It rechecks the executable hash before every call. Only encrypted bytes are temporarily copied to scratch storage; those copies are deleted on success, failure or timeout. Subprocess output is captured, bounded by a timeout and never echoed on failure.

The native helper validates the prepared recipient metadata and certificate pin, insists on an encrypted private-key file and limits Keychain retrieval to this application's fixed local recipient service and the metadata's UUID account. It does not accept arbitrary Keychain service queries or return a passphrase/private key. The unlock secret goes only through an anonymous stdin pipe to OpenSSL. Provider diagnostics are suppressed. CMS plaintext is retained in native memory until authentication has completed successfully; only then is it returned on the private parent pipe. No plaintext evidence or passphrase file is written.

macOS can ask the user to authorize a newly compiled helper's access to this dedicated item. The user must complete any local Keychain prompt themselves; never request their password in chat. Failure or timeout admits no plaintext and never triggers more AWS reads, a replacement capture or permission widening. After local authorization, retry only verification of the already retained encrypted files. The user may choose persistent access to the dedicated item for a helper they trust; the application does not silently grant that access.

The bridge assumes a trusted operator and host. Hash pins/private permissions do not authenticate capture authors, make an untrusted compiler trustworthy, defeat a malicious account owner, or prove cloud delivery. Preserve the independent certificate pin, encrypted recipient key and its Keychain item. Current capture flags still prohibit treating a verified retrospective archive as prospective trial evidence.

Portable tests use fake subprocesses and dummy files; Linux CI never accesses a real Keychain or private key. Tests check private ciphertext scratch, cleanup after nonzero exits/timeouts, source/helper changes, certificate substitution, permissions, symlinks and generic secret-safe failure messages. Native compilation and local authorization are separate platform verification steps, with real administrative artifacts retained privately.
